# Contributing to i-dream

Thanks for considering a contribution. i-dream is built solo right now but PRs and issues are welcome.

## Quick orientation

- **Rust daemon + CLI** — `src/`. Entry: `src/main.rs`. Five modules under `src/modules/` (dreaming, metacog, intuition, introspection, prospective + the new weekly_briefing, project_briefs). Shared infra in `src/{api, config, daemon, dashboard, dream_trace, events, hooks, logging, store, transcript, widget, graph_metrics}.rs`.
- **Swift menubar widget** — `tools/menubar/i-dream-bar.swift` (single 8000-line file).
- **HTML dashboard** — generated by `src/dashboard.rs::render_html`. Lands at `~/.claude/subconscious/dashboard.html`.
- **Docs** — `docs/`. The README docs index has every entry.

## Local dev loop

```bash
# Rust changes
cargo test --release --bins
bash scripts/install.sh              # builds + installs atomically (tmp + mv)
# NEVER cp over ~/.local/bin/i-dream in place: overwriting a signed Mach-O
# reuses the vnode and invalidates the kernel's cached code signature, and
# the next launchd spawn gets SIGKILLed (OS_REASON_CODESIGNING) or EX_CONFIG.
# This killed the 2026-07-12 02:30/02:45/03:00 nightly jobs.

# Swift changes
bash tools/menubar/build.sh          # builds + ad-hoc signs + relaunches
```

## Before opening a PR

```bash
cargo fmt --all
cargo clippy --all-targets --release -- -D warnings
cargo test --release --bins
bash tools/menubar/build.sh          # if Swift changed
```

## Conventional commits + versioning

- One logical change per commit. Imperative subject ≤72 chars. Body explains the *why*, not just the *what*.
- For any user-visible feature or fix:
  1. Add an entry to `CHANGELOG.md` under `[Unreleased]`
  2. Bump `Cargo.toml` `version` (patch for fixes, minor for features, major for breaking changes)
- Co-author tag for AI-paired commits: `Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>`

## Code style

- Rust: defaults from `cargo fmt`. Module-level docs at the top of each file. `#[cfg(test)]` blocks at the bottom.
- Swift: 4-space indent, follow the existing `i-dream-bar.swift` patterns (single-file app). Use `dlog(...)` for runtime logging — those land in `/tmp/i-dream-bar.log`.
- Names: prefer descriptive over short. The codebase favors readable identifiers + comments that explain *why*, not *what*.

## Filing issues

Use the templates under `.github/ISSUE_TEMPLATE/`. Bug reports should include the daemon log tail and `i-dream --version`.

## Architecture pointers for new contributors

- **Where dreams come from**: `src/modules/dreaming.rs::run_sws → run_rem → run_wake`
- **Where the SessionStart briefing is built**: `src/daemon.rs::build_session_start_response`
- **How the dashboard is generated**: `src/dashboard.rs::Snapshot::collect → render_html`
- **How the menubar menu is built**: `tools/menubar/i-dream-bar.swift::populateMenuItems`
- **Where the floating HUD lives**: `tools/menubar/i-dream-bar.swift::showHUD / updateHUDContent`

## Running the daemon during development

```bash
# Foreground (logs to stderr)
i-dream start

# Background as a launchd agent
i-dream service install
i-dream service start

# Trigger a cycle manually
i-dream dream
```
